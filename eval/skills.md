# Available Skills

## How to Use Skills

Skills are automatically triggered when you ask a question that matches their description. You can also explicitly trigger a skill by using the phrase in the "Trigger" column.

| Skill | How to Trigger/Use |
|-------|-------------------|
| `agent-architecture-analysis` | Ask: "analyze agent architecture", "12-factor audit", "how compliant is this agent", or "evaluate this LLM app". Use when auditing agent codebases or comparing frameworks. |
| `caveman` | Say "caveman mode", "talk like caveman", "use caveman", "less tokens", "be brief", or use `/caveman`. Switch levels: `/caveman lite`, `/caveman full`, `/caveman ultra`. Stop: "stop caveman" or "normal mode". |
| `customize-opencode` | Use ONLY when editing opencode config files: `opencode.json`, files under `.opencode/`, or files under `~/.config/opencode/`. Also use for creating/fixing opencode agents, subagents, skills, plugins, MCP servers, or permission rules. |
| `documentation-audit` | Ask: "audit docs", "verify documentation", "check docs", "docs accurate", "documentation drift", "before release", "after refactor", or "docs don't match". Uses two-pass extraction for comprehensive detection. |
| `documentation-writer` | Use for creating high-quality software documentation. You'll be guided through the Diátaxis Framework workflow: clarify document type (Tutorial/How-to/Reference/Explanation), target audience, user's goal, and scope. |
| `find-skills` | Ask: "how do I do X", "find a skill for X", "is there a skill that can...", or express interest in extending capabilities. Helps discover and install agent skills. |
| `frontend-design` | Use when building new UI or reshaping existing one. Helps with aesthetic direction, typography, and making design choices that don't read as templated defaults. |
| `grill-me` | Say "grill me" to trigger a relentless interview that sharpens a plan or design. Useful for stress-testing ideas before implementation. |
| `laravel-patterns` | Use for Laravel architecture patterns, routing/controllers, Eloquent ORM, service layers, queues, events, caching, and API resources. Covers production app development. |
| `pentest-business-logic` | Use for business logic vulnerability testing: workflow bypass, payment manipulation, state machine abuse, and function limit circumvention. Follows WSTG-BUSL methodology. |
| `requesting-code-review` | Use when completing tasks, implementing major features, or before merging to verify work meets requirements. Helps ensure code quality. |
