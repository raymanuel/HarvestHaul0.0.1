# HarvestHaul — Deployment Guide

> Last updated: 2026-07-18
> Laravel 12 · PHP 8.2+ · MySQL · Tesseract OCR · Poppler

## 1. Server Requirements

| Requirement | Version | Notes |
|-------------|---------|-------|
| **PHP** | 8.2+ | Extensions: `pdo_mysql`, `mbstring`, `openssl`, `json`, `bcmath`, `gd`, `intl`, `fileinfo`, `curl`, `xml`, `zip` |
| **MySQL** | 5.7+ / 8.0+ | `utf8mb4_unicode_ci` collation. MariaDB 10.5+ also works. |
| **Composer** | 2.x | |
| **Node.js** | 18+ | Only needed for frontend build (Vite). Not required at runtime. |
| **Tesseract OCR** | 5.x | System-level binary. Required for DA RFO12 price scraper only. |
| **Poppler** | 22+ | Provides `pdftoppm` for rendering PDF pages as high-DPI images. Required for PDF-based price scraping. |

## 2. Tesseract OCR Installation

The `crops:scrape:darfo12` command uses Tesseract OCR to extract prices from DA RFO12 blog images and PDFs. **All other features work without Tesseract** — it only affects the daily price scraper.

### Ubuntu / Debian

```bash
sudo apt update
sudo apt install tesseract-ocr
# Verify
tesseract --version
```

### CentOS / RHEL / AlmaLinux

```bash
sudo yum install tesseract
# or
sudo dnf install tesseract
```

### Windows (Dev)

```bash
winget install tesseract-ocr.tesseract
# Or download from: https://github.com/tesseract-ocr/tesseract/releases
```

### Docker

```dockerfile
RUN apt-get update && apt-get install -y tesseract-ocr && rm -rf /var/lib/apt/lists/*
```

After installation, set the `.env` variable:

```ini
# Linux (default PATH lookup)
TESSERACT_BINARY=tesseract

# Windows (full path required)
TESSERACT_BINARY="C:/Program Files/Tesseract-OCR/tesseract.exe"
```

## 2b. Poppler Installation

The PDF-based price scraper uses `pdftoppm` (from Poppler) to render PDF pages as 300 DPI PNG images for OCR. This provides much better OCR accuracy than the old blog image approach.

### Ubuntu / Debian

```bash
sudo apt update
sudo apt install poppler-utils
# Verify
pdftoppm -v
```

### CentOS / RHEL / AlmaLinux

```bash
sudo yum install poppler-utils
# or
sudo dnf install poppler-utils
```

### Windows (Dev)

```bash
winget install oschwartz10612.Poppler
# Or download from: https://github.com/oschwartz10612/poppler-windows/releases
```

### Docker

```dockerfile
RUN apt-get update && apt-get install -y poppler-utils && rm -rf /var/lib/apt/lists/*
```

After installation, set the `.env` variable (optional — defaults to PATH lookup):

```ini
# Linux (default PATH lookup)
POPPLER_PDFTOPPM=pdftoppm

# Windows (full path if not in PATH)
# POPPLER_PDFTOPPM="C:/poppler/Library/bin/pdftoppm.exe"
```

Copy `.env.example` to `.env` and configure:

```bash
cp .env.example .env
php artisan key:generate
```

The app is configured for `Asia/Manila` (UTC+8) in `config/app.php`. The DA RFO12 scraper runs at 6:00 AM, 11:00 AM, 4:00 PM, and 9:00 PM Manila time.

## 6. Scheduling (Cron)

The app uses 9 scheduled commands. Add a single cron entry to your server:

```bash
* * * * * cd /path/to/harvesthaul && php artisan schedule:run >> /dev/null 2>&1
```

Or use `schedule:work` for development:

```bash
php artisan schedule:work
```

### Scheduled Commands Summary

| Command | Frequency | Purpose |
|---------|-----------|---------|
| `delays:check` | Every 15 min | Stall/stop/GPS loss detection + auto-escalation |
| `weather:check` | Every 30 min | Weather per waypoint (depot + farms + destination) |
| `deliveries:auto-complete` | Hourly | Auto-complete deliveries awaiting confirmation >48h |
| `deliveries:auto-complete-stale` | Hourly | Auto-complete stale in_progress deliveries >48h |
| `invoices:generate` | Hourly | Generate PDF invoices for completed jobs |
| `proposals:auto-reject-expired` | Hourly | Auto-reject pooling proposals pending >48h |
| `negotiations:auto-close-stale` | Daily | Close negotiations inactive >7 days |
| `crops:scrape:darfo12` | 6:00, 11:00, 16:00, 21:00 | Scrape DA RFO12 prices via PDF+OCR pipeline (4x daily) |
| `data:cleanup` | Daily | Purge old tracking records, notifications, weather logs |

## 7. Queue Worker

The app uses database queues (`QUEUE_CONNECTION=database`). Start a worker:

```bash
php artisan queue:work --sleep=3 --tries=3
```

For production, use a process manager (Supervisor, systemd):

```ini
# /etc/supervisor/conf.d/harvesthaul-worker.conf
[program:harvesthaul-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /path/to/harvesthaul artisan queue:work --sleep=3 --tries=3
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=2
redirect_stderr=true
stdout_logfile=/path/to/harvesthaul/storage/logs/worker.log
```

```bash
# 4. Test Poppler is accessible

# 5. Test the scraper (dry run — will attempt to scrape DA RFO12)
php artisan crops:scrape:darfo12

# 6. Verify scheduler
php artisan schedule:list

# 7. Check queue worker is running
php artisan queue:work --once
```

## 12. Known Deployment Notes

### PHP Version Compatibility

The project includes a `scripts/fix-pdo-mysql.php` post-install hook that patches a Laravel 12.64+ incompatibility with PHP 8.2/8.3 (replaces `use Pdo\Mysql` with `constant('PDO::MYSQL_ATTR_SSL_CA')`). This runs automatically on `composer install`.

### Database: MySQL vs SQLite

- **Production**: MySQL (`DB_CONNECTION=mysql`)
- **Testing**: SQLite in-memory (`phpunit.xml` overrides `DB_CONNECTION=sqlite`, `DB_DATABASE=:memory:`)
- Do NOT use SQLite in production — the app uses MySQL-specific features (JSON columns, full-text search, etc.)

### Tesseract OCR on Shared Hosting

Shared hosting typically does not allow system binary execution. The `crops:scrape:darfo12` command will fail. Options:
1. Run the scraper on a separate VPS/server with Tesseract and Poppler installed
2. Write a custom API endpoint that writes directly to `crop_price_history`
3. Skip the scraper and manually populate `crop_price_history`

### Poppler on Shared Hosting

Poppler (`pdftoppm`) is required for the PDF-based scraper (primary data source). If unavailable, the scraper falls back to bantaypresyo.da.gov.ph structured HTML scraping, which produces fewer commodities (~32 vs ~55).

### InfinityFree / Free Hosting

Prepared credentials exist in `.env` (commented out). These hosts have limitations:
- No system binary access (Tesseract won't work)
- Limited PHP execution time (scraper may timeout)
- No queue worker support (use `sync` queue instead)

### Crop Price History Table

The `crop_price_history` table has a unique constraint on `(commodity_name, source, source_date)`. This ensures the `crops:scrape:darfo12` command uses `updateOrCreate` correctly — updating existing entries rather than creating duplicates. The PDF scraper adds Imported/Local suffixes (e.g., "Glutinous (Imported)", "Glutinous (Local)") to differentiate origin variants within the same commodity.

### Scraper Status Table

The `scraper_status` table logs every scraper run with status (`success`, `failed`, `skipped`), source date, matched/skipped record counts, and error messages. The Market Prices Card uses this to show warnings when the scraper fails or hasn't run yet.

## 13. Quick Start (Development)

```bash
git clone https://github.com/raymanuel/HarvestHaul0.0.1.git
cd HarvestHaul0.0.1
composer setup          # Installs deps, copies .env, generates key, migrates, builds frontend
php artisan serve       # Start dev server at http://localhost:8000
```

In a separate terminal:

```bash
php artisan schedule:work    # Start scheduler
php artisan queue:work       # Start queue worker
php artisan websocket:serve  # Start WebSocket server (optional)
npm run dev                  # Start Vite dev server (optional)
```
